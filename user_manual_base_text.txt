I want to make a user manual which will explain users how to operate our website and what they can do.

Company Coordinator : 

1. On the home page, the coordinator will see a overall status (total user, total RACMs, Approved/Rejected RACMs) and tabs which links to different pages. Units will be shown which are under the coordinator.

2. User Management : In this section all users will be listed unit wise. Approvers from all over the company will be listed here, on click the page will show their current assignments. 

Coordinator can create users by manaul form or bulk excel upload. 
Clicking on the plus icons will open a form for user creation. Select for which units user should be created and fill in rest of the details. Multiple units can be selected and mobile number and email are mendatory field details for user creation. It is advised to user organization email address only.

For bulk upload, it is required to fill the users details per row in provided template. Make sure to enter accurate details, as invalid email or mobile number will prevent the user creation.

Coordinator can link users to other units even after creation. For that click on unit row and update units in in pop-up window.

Deleting a user will remove the user account and all linked RACMs will become inactive. 

There is an option to export users data, by clicking export button.


3. RACM Communication : In this section emails can be added for a specific business process or for all processes. Option to choose unit is also give. Added emails will be included in cc list of all emails related to that RACM of Business process.

4. RACM Templates : In this section coordinator can add column fields for RACM creation and save it as a seperate template, which can be used later on. 

Some standard columns come pre-defined and can't be changed. We also provide standard set of assertion columns to add, so user can add according to requirement.

After creating a template make it active, so in next step (RACM creatio/upload) that template will be used to create RACMs.

There can be multiple templates in a single unit, but only one can remain active at a time.

There is also an option to import templates from other units of the company if required.



5. RACM Create/Upload

In this section coordinator can create RACMs by uploading excel file or by manually form submission.

First you need to review the sample size for each control frequency, by clicking on Sample Size Settings button. Option to modify the sample size is also provided, within min-max limit. Based on the sample size, the dates and interval will be auto generated. 

In the file upload section upload the controls excel file, select the business process, unit and financial year. Providing reminder settings is option, if it is different for all. That can be configured later on in bulk manner. In header detection keep the default option, if program fails to detect header then you have to select "User Excel Row number" option and write the header index. After that user will be asked two options "Use automatic mapping" and "Adjust column mapping". Selecting first option will create RACMs based on auto selecting columns (some columns may not get matching target field). It is advised to use the later one, because user will have ability to configure all columns from excel file to template columns. Control numbers will auto generate if not selected from excel file and configuring control frequency is mendatory before final submit.

In case if control frequency has a value which is not recognized by the program, then it will prompt you to select its corresponding category. RACMs will be created after performing these steps.



6. RACM Management

In this section all RACMs will be listed with various filters and options. It is advised to first set due date of RACMs. For that there is a button  "Set Due Date" which will allow to set due date of multiple RACMs in single click. (It will override if any selected RACM already has a due date). After due date is set, RACMs will be listed in RACM Assignment page, where process owner assignment will take place. (Point No. 7).

"View Docuemnts" button will list all RACMs with valid process owner assignment and number of document uploaded.

"Replicate" button is useful if coordinator want to create a replica of an existing RACM for next financial year. With these only basic details will be replicated process owner, due date and other approval related data will not be included.

Clicking on a row will open that particular RACM in new page, where full details will be shown. In this page coordinator can modify due date, upload sample documents, perform RACM assignment (this will set RACM to active if other conditions satisfy, only Active RACMs will be shown to process owner). There is also an option of self-assignment, which will be available in more actions. Performing self assignment will make you the process owner of that RACM, and now it is your responsibility to upload docuemnts and send it for approval.



7. RACM Assignment



Approver : 

1. On the home page, the approver will see a snapshot of approval activity (total, pending, approved, and rejected RACMs) and links to the Approval Dashboard and Company Details. RACMs are assigned by company admin or coordinator based on assignment scope — unit level, unit + business process level, or RACM-specific assignment. When scopes overlap, the more specific assignment takes precedence.

2. On the Approval Dashboard, the approver will see all RACMs which are submitted by process owner. The dashboard includes filters for approval status, business process, financial year, unit (when more than one unit is in scope), conclusion, and control number search. By default, pending RACMs are shown. Clicking a RACM opens it in a new window with all important details listed on top.

3. Each RACM has the same major sections as the process owner view: (1) Process and Risk, (2) Control Details, and (3) Assertions (may not exists in some). The approver can review evidence/documents uploaded by the process owner. Audit logs and RACM history are also available from the RACM page.

4. For RACMs with status "sent for approval", the approver must either Approve or Reject the RACM.

(1) Approve — The approver must fill in Design and Implementation details: procedures taken to evaluate the control, and conclusion (Effective / Not Effective / Accepted under deviation). If the conclusion is Not Effective, a description of the deficiency is required. Reason for approval is optional.

(2) Reject — The approver must provide a reason for rejection. The process owner will need to upload at least one new document and resubmit the RACM.

5. After the initial approval decision, there are three main outcomes :

(1) RACM Rejected — Process owner must resubmit with at least one new document.

(2) RACM Approved - Not Effective — Process owner (or coordinator) must submit a deficiency response: either a Mitigation Plan or Compensatory RACM. The approver will see the submitted response on the RACM page and must review it.

(3) RACM Approved - Effective / Accepted under Deviation — No further action is required.

6. Deficiency response review — When a deficiency response is submitted, the dashboard shows an "Action Required" alert. On the RACM page, the approver can approve the response as Effective or Accepted under deviation, or reject it. Rejection requires a comment. If rejected, the RACM remains Not Effective and another response is required from the process owner.

7. Types of deficiency responses (for reference when reviewing):

(1) Mitigation Plan — Includes explanation, concerned person, and due date (today or a future date).

(2) Compensatory RACM — Includes explanation and at least one uploaded document.









Process Owners:

1. On dashboard user will see all assigned RACMs list. RACMs will be assigned by respective coordinator. Dashbaoard includes various filters, which can be used to make it easy to find target RACMs or have an idea of status of them.


2. On click RACM will be opened in new window with all important details listed on top. Each ramcs will have two major sections 1. Process and Risk 2. Control Details. third one is assertion, which may not be available if coordinator has not defined it. 
RACMs will have sample docs provided by company coordinator for reference. Some RACMs may not have them. 
Based on control frequency and sample size set by coordinator, dates/intervals for sample required will be provided in excel format.
User will have to upload evidence/docuemnts and submit the RACM for approval. User can't remove a document once it is uploaded. Writing remakrs is optional.


3. User can request chnages in RACM if necessary. On top-right corner a button will be provided for requesting changes. User can request to chnage due date and other majority of fields in RACM. Business process and Control frequency can't be changed. 
For this user need to click on "Request Change" button and all fields will become editable. Change them and providing a reason is optional but recommanded. Coordinator will review the requeted changes and will approver/reject individual fields. After successfull review the user will see it in Change Request option. For rejected fields coordinator will also provide remarks. 

User can't request chnages in RACMs which are sent for approval.


4. Approver will either Approver or Reject RACMs upon their judgement. There are three cases after that.
(1) . RACM Rejected.  For rejected RACMs user will have to resubmit the RACM by uploading at leat one new document, User can remove old documents before re-submitting.

(2) . RACM Approved - Not Effective. Means RACM's documents were relevent but did not meet the requirement. In this case user need to submit a deficiency response with will be either Mitigation plan or Compensatory RACMs. In RACM Page user will have information of procedures taken to evaluate and description of deficiency in "Design and Implementation" section. Coordinator can also submit the deficiency response, so it should be agreed in advance who will submit it.

(3) . RACM Approved - Effective/Accepted under Deviation. This means the RACM is approved as Effective or Accepted under Deviation. No further action is required.


5. Types of Deficiency responses
(1) . Mitigation Plan = Requires explanation, concerned person, and due date (today or a future date).

(2) . Compensatory RACM = Requires explanation and at least one uploaded document.


6. Deficiemcy responses are also subject to the judgment of approver. if rejected, RACM will still remain Ineffective and requries another response. If approved, RACM will be either Effective or Accepted under deviation, no action required.
